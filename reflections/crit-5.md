# Crit 4 reflection

## What was the breakthrough that moved the work forward?

The breakthrough was manually verifying the game dynamics and judging the fairness of the game logic from the perspective of a player. The notion of simplicity came to mind when playing the game by hand and that is what I used as my acceptance criteria for stopping further iterations. The game had to be a single function, no distractions game. The game logic was intended to be naive to allow a player to get completely engrossed in one goal - maximising the points. There was only one way to do so: collect more red dots. Capturing the intention and building the acceptance criteria for the UI design proved to be the breaking barrier between almost done and finished.

## What did this work change about who I want to be as a software developer?

This work affected my reflection of the previous crit in which I had written that manual verification should be minimised, I would like to change that statement and say, the technical sections of software development can be left to automated verification, but anything that requires a human to interact, manual testing should be spread even more broadly. Multiple focus groups should be formed to get real feedback from real customers. This makes me realise that a "correct" solution is not always the "right" solution. To make something people need, the need has feel "solved" by the customer.
